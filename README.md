## The owner's standing rules (earned across 30 projects; apply without re-asking)
1. **Playable first.** Something the owner can open on Pages and play beats test coverage. Every stage ends in something clickable, with a screenshot.
2. **Fidelity is the product.** Mechanics ported 1:1 from the current edition; never tune printed numbers; log every ambiguity as `RULING: <rule> | <what we did> | <why>` with a status word instead of blocking.
3. **"Mallet posture" on IP.** Real unit/weapon/ability/team names are fine; all prose (rules text, lore, UI copy) in our own words; no publisher art, icons or logos; official PDFs and community data stay in gitignored `docs/sources/`; README and UI say "unofficial, non-commercial fan project". GW iconography in generated figures is an accepted playtest placeholder.
4. **Do the legwork; research before assuming.** Free downloads, $0 checkouts, Vassal modules, fan wikis via curl, product photos: all fair game. Only stop for passwords, payment or account creation. Never ship a stand-in or "unverified" value after one blocked source.
5. **Answer before building.** When the owner asks questions, answer and propose, then wait for the go. Explicit instructions mean act.
6. **Cost-sensitive.** Sonnet implements, the session model integrates and verifies only where rules are dense; one or two agents per milestone with exact file lists; no adversarial review loops by default; about 2.5M tokens per push; check-ins of 10 lines or fewer. Mallet's big-spec experiment (4.8M before anything playable) is not to be repeated.
7. **Art direction is set once per project and not re-litigated.** For 40k that is MGSD (about 2-2.5 heads, head about 40% of height). Check the image, not the prompt. Concept approval is delegated to Claude; send contact sheets as FYI. Lock the figure look early (a late lock threw away a whole v1 set).
8. **No native tooltips in games**, prompts name what they decide, open information is a rule, never assume a choice, every displayed number comes from the engine.
9. **Audio is judged by ear on `sounds.html`**; say "not verified by ear" until the owner listens. The synth score was rejected once ("the music sucks"), so real generated music is expected. Since 2026-10-17 the local Audio Studio replaces ElevenLabs.
10. **GPU etiquette:** announce GPU work; never two GPU jobs at once; never kill node by image name. The owner waived the ask-first gate on 2026-10-17 for Fell-in and said to use the studios to develop the look and sound.
11. **Privacy:** credit "evilgouki"; never the real name or home path in anything that can become public; grep before every commit.
12. Questions go through the multiple-choice UI, batched (two batches of at most 4), recommended option first, everything else stated as a default.
13. **Pipeline everything; never idle a stage.** Each finished item moves to the next stage straight away: a concept PNG goes into the GLB queue the moment it renders, and a GLB is finalised and wired the moment it lands. Both GPUs (this PC and Alteisen) stay busy while concepts are still coming. The same goes for code: a team's verification starts when its implementer finishes, not when the whole batch does. Waiting for a full batch before starting the next stage was called out as inefficient (Murder Squad, 2026-10-18). **Quality gates also run per item, inside the stream.** Each concept passes a measurable check before it is kept: a side-by-side with an on-style reference figure, a head of about 35-40% of figure height, and about 2-2.5 heads overall. The coordinator reviews the first image and the contact sheet of each team before that team's GLBs start. "Check each image" with no concrete reference let 32 off-model concepts through, and the owner caught it, not us (2026-10-24).
14. *(added 2026-10-26, Murder Squad PLAN, owner)* **Official sources replace invented content as soon as they exist.** Three invented killzone layouts were deleted and replaced by the six official tournament cards measured on the 1" grid (2026-10-18); buildings are drawn from the rules geometry because generic GLB walls let operatives "walk through" walls (owner bug report 2026-10-22).
15. *(added 2026-10-26, Murder Squad PLAN, owner)* **Figure look and poses are an owner decision made once, early.** Murder Squad's v1 (bare-handed A-pose bodies + weapon attachments) was replaced the next day by dynamic-pose bodies with weapons fused in ("A-poses look generic"); the owner also banned model-kit brand and "mecha"/"robot" words in figure prompts and docs (the style sentence is derived from his reference pictures, `docs/spec/30-figures.md` section 1). Skeletal animation was piloted and dropped (2026-10-18); do not reopen it for fused Hunyuan meshes.
16. *(added 2026-10-26, lorecannae)* **The UI skin should suit the setting.** "I like how starbound legions presented because it was appropriate to the Star Wars universe. This is not Star Wars." Keep the structure, re-skin the look. Recognisable subjects matter ("Darkwing Duck not being a duck is really bad").
17. *(added 2026-10-26, Murder Squad PLAN, owner)* **Stop the local studio services when a session is done with them** ("Stop the services. We're not using them."); the main PC runs Hunyuan batches only after they are stopped and commit charge is checked.
18. *(added 2026-10-28, Legion Forge kickoff, owner)* **The Mallet posture holds even for a Disney property.** Offered the Starbound Legions posture (original names with a switchable real-name file) because Disney shut down the Pixelborn simulator in 2024, the owner chose real names everywhere for Star Wars: Legion. The concern was stated once, in the question; don't repeat it. Figures show recognizable Star Wars designs in MGSD style ("recognisable subjects matter", rule 16).
19. *(added 2026-10-28, Legion Forge kickoff, owner)* **Keep the knowledge base current during development**, not only at kickoff: every milestone updates that project's KB entry and adds new cross-project lessons here, so the next game starts from it.
20. *(added 2026-10-28, Legion Forge, owner)* **Ask during development, never block on the answer.** "Ask clarifying questions if needed during dev, don't block dev if at all possible when asking questions. I'll answer as quick as I can." Pattern: write the recommended option into PLAN.md as the default, keep building on it, put the question to the owner while background agents run, and revise when the answer lands.
21. *(added 2026-10-30, shadowforge, owner)* **Every game gets its own look and feel. A template supplies the structure, never the skin.** "The look and feel is too much like Lorecannae. I wanted it to be unique look and feel for each game ... Xross forge is an excellent example." Shadowforge (Shadowverse: Evolve) copied lorecannae's interface and only re-coloured it: the same centred menu dialog, gold filigree frames, star card backs, serif type, board frame and hand fan. Xross Forge started from the same lorecannae scaffold and is the model: one presentation concept drawn from the game's own world (its D7, "esports broadcast stage", because Xross Stars is a streamer card game), carried through every surface: the title (CSS wordmark, crossing stage beams, a scrolling perspective floor), the HUD as a broadcast scoreboard, the event feed as a lower-third caption bar, a "REC" ticker, neon card frames, its own card backs, type, motion, music and an original announcer. **How to apply:** at kickoff write a one-line presentation concept tied to the game's identity, plus a "must not look like" list naming the template and the last two siblings, and get the owner's yes on it with the art audition. Keep the template's layout rules and modules (rule 16: keep the structure), but rewrite every visual token: palette, typefaces, frame shapes and ornaments, card backs, zone shapes, title and menu screens, transitions and stingers, icons, music and voice. Before the first playable ships, put screenshots of the title, the deck picker and a mid-game board beside the template's and the previous game's; if one could be mistaken for the other, it is not done. Re-colouring is not re-skinning.

## The proven build recipe (what every 3D port since Mallet has done)
1. **M0 scaffold** copied from the previous sibling (Vite 8 + React 19 + three 0.186 + R3F 9 + drei 10 + zustand 5 + TS 7 strict + Vitest 5 + Playwright + ajv + tsx; `deploy.yml` to Pages; `vite.config.ts` with sub-path `base`, chunk splitting and a second `sounds.html` entry; `playwright.config.ts` with `PW_PORT`; `.gitignore` for secrets, PDFs, `docs/sources/`, `e2e-out`, `tools/out`; `.gitattributes` LF for workflow scripts; `.claude/launch.json`). Write `CLAUDE.md`, `PLAN.md`, `HANDOFF.md`, `STATUS.md`.
2. **Specs** `docs/spec/00-architecture` (frozen contracts, one pending decision, `legalActions` never empty, rejections never throw, `view(state, seat)`, `query.*` owns every number), `10-rules-core`, `11-missions`, `12-rules-test-checklist` (stable IDs, lean), `13-golden` (a worked turn with forced dice), `20-data-schema` (+ JSON schemas, frozen only after a dry run over every unit in the first slice), `30-figures`, `40-ai`, `50-client`, `60-testing`, plus an edition leak list.
3. **M1 data** with a `source` per record and `validate:data`.
4. **M2 engine** (pure reducer, seeded RNG, action log, replay, headless `sim` with invariants and a stall cap, tests named by checklist ID, `action-fuzz`).
5. **M3 playable slice** on Pages with procedural stand-in figures, a random bot, briefing, objective tracker, dice tray, event feed, explanatory prompts, presentation director with presented-state cursor and bot idle wait.
6. **M4 AI** (utility decider in a Web Worker, tiers, `ai-bench` gate: normal beats random >= 95%).
7. **M5 art** (concepts -> Hunyuan GLBs -> `models:optimize` -> `?gallery` check -> wire), streamed: launch the GLB agent alongside the concept agent, polling the concept folders and queueing each new PNG on whichever GPU frees up first. Also terrain and boards, army painter.
8. **M6 audio** (weapon-flavour map first, manifest, idempotent generator, `measure-audio` trims, `sounds.html`, music director with calm/battle/tense/victory/defeat).
9. **M7 polish** (narration pauses, hover help, settings, end screen, phone layout via Mallet's form-factor layer).
10. More teams/factions in parallel worktrees, one Workflow run apiece.

## Gotchas that bit more than one project
- `legalActions` empty froze the bot (Mallet twice, WarMech once). Zero-cost reactions loop forever (one per window plus a stall cap).
- The UI must never do rules maths; read roll targets from state, not the last event.
- Bot acting ahead of animations; results drawn behind the prompt that asks about them.
- Concurrent `npm install` corrupts `node_modules`; Sonnet agents backgrounding long commands stall; one stage at a time; commit after each stage; after a dead run, `git status`, gates, commit by hand.
- `models:optimize` writes meshopt; `GLTFLoader` needs `setMeshoptDecoder` or every GLB silently falls back to the procedural figure.
- Quadrupeds/side-view concepts face the wrong axis (per-unit `yaw` in the manifest); check `?gallery` close-ups, the overview camera hides problems.
- Hunyuan style reference turns everything blue (`--style 0.2 --avoid`); floor-length capes need `--nocut`; Hunyuan paint flattens to pale tan (re-grade); image-to-3D cannot do flat terrain; terrain above about 6k tris costs frame time.
- Gemini: drifts to 6-7 heads unless the head size is stated in numbers and checked in the image; new free-text follow-ups drift, so edit one clean base image per faction; about 30 images per evening; "Download full size" is unreliable (fetch with `?alr=yes`); never paste from the clipboard (private text leaked once); 1 in 17 replies is text only.
- Flux: a proper noun invites lettering; vague nouns get filled by the model's prior; "magazine cover" draws a title banner.
- Audio: one sound per weapon until the flavour map existed; AI gunshots come back with crest factor 2 (real 8-20), so measure and layer; ElevenLabs charged for 502s. Describe the mechanism, state exclusions.
- PowerShell 5.1 writes a UTF-8 BOM (Python `json.load` fails); Git Bash `/c/...` paths break Windows Python; Git Bash eats backslashes in `sed -i`; `/tmp` is invisible to node; the built-in browser pane cannot drag three.js models (use Playwright `page.mouse` with >= 10 steps) and can lose WebGL (use `npx playwright screenshot`).
- Playwright port reuse serves a stale sibling build; give each worktree its own port. CI runners are about 2x slower (30 s vitest timeout, raised AI timing ceilings).
- Secrets: ignore `*.token*`, `Tokens.txt`, `tokens.txt*`, `.env*`; read keys only into env vars; personal paths/name once leaked into a public repo's history.
- HANDOFF.md goes stale fast; rewrite STATUS.md instead of appending; `ls` every path a doc claims.
- *(added 2026-10-26)* **Check which checkout is current before copying a sibling:** Murder Squad's local `main` was 70 commits behind `origin/main` and the newest code was only visible via `git worktree list`. Docs also lag the log (STATUS said batches C/D had no figures a day after they landed).
- *(added 2026-10-26)* **The pre-commit privacy hook does not protect git worktrees** (`.git` is a file there, so the pattern file is not found and the check passes silently): grep the staged diff for the name and home path by hand, or point the hook at `git rev-parse --git-common-dir`.
- *(added 2026-10-26)* Parallel agents on Windows write CRLF/LF mixes (whole-file diffs): `.gitattributes` `* text=auto eol=lf`, `*.bat text eol=crlf`, renormalise once.
- *(added 2026-10-26)* Hunyuan 2.1 shape needs about 40 GB of Windows commit charge; a failed shape stage is masked by a stale `shape.glb` being re-painted (clear them, require `shape done` per slug); launch long remote jobs detached with `schtasks`; the second PC's C: drive was nearly full (TEMP on E:).
- *(added 2026-10-26)* iOS Safari resumes an AudioContext only from `touchend`/`pointerup`/`click`: keep the unlock listeners for the session and retry (Mallet M12 fix); overnight Gemini batches stall after about an hour behind the Windows screen lock (keep-awake does not stop it); Claude in Chrome may default to the Mac browser.
- *(added 2026-10-26)* The Audio Studio exists only on an unmerged worktree branch of the `3D Model Generation` repo; a shared-GPU reservation file (`C:\Claude Code Projects\.gpu-lock`, protocol in lessons-since-2026-10-17.md section 5) was used by lorecannae and Murder Squad on 2026-10-24.
- *(added 2026-10-26)* Per-item art gates need a concrete reference (side-by-side with an on-style figure, measured head ratio): a vague "check each image" let 32 off-model concepts through (rule 13 above already says this).
- *(added 2026-10-28)* **The KB is copied into each repo and drifts.** By 2026-10-28 three copies existed with different contents (murder-squad 9 files, mancermundo 14, none in mallet-42k), and sibling commits from 10-27 were in no copy. Start a new project from the newest copy (compare file lists and last-commit dates), say in the README which copy it came from, and digest sibling commits newer than that copy. A single KB repo that every game links to would remove the drift (not done yet; the owner's call).
- *(added 2026-10-28)* **Cloud sessions (claude.ai/code) are a different machine.** They run in a Linux container with no GPU, no local AI studios (Hunyuan, Flux, Audio Studio), no Claude in Chrome/Gemini and no `gh`; GitHub goes through MCP tools, and public sibling repos clone anonymously through the git proxy (`git clone --depth 1 https://github.com/dragoonant/<repo>`). Engine, data, AI and client stages run fine there; art and audio stages must run from a session on the owner's Windows PC. Files outside a pushed commit are lost when the container is reclaimed, so commit and push after each stage.
- *(added 2026-10-29, Legion Forge)* **Background agents' final replies can be lost** (two container restarts on 2026-10-29 kept every file the agents wrote but dropped their hand-back summaries). Have each agent write its summary into a file it owns and read that, not the transcript.
- *(added 2026-10-29, Legion Forge)* **Publisher card PDFs are often image-only.** Check for a text layer before planning data entry; community list-builder bundles (e.g. a live JS bundle with embedded card JSON) can be the only machine-readable source, and they can disagree with the printed card, so primary wins and every playable faction gets an eye check.
- *(added 2026-10-29, Legion Forge)* **`git mv` by a running agent stages into the shared index**, so the coordinator's next `git add <paths> && git commit` also commits the agent's half-finished renames (Legion Forge's M1 commit swept in M2a's engine moves and went red; caught by gating the commit in a clean worktree before the push). While agents run, commit with `git commit -m ... -- <paths>` (only those paths) and gate the commit in `git worktree add <tmp> HEAD` with `node_modules` symlinked, never the working tree. Same day, a plain `git add -A` for a docs change swept 20 of another agent's half-written data files into a pushed commit.
- *(added 2026-10-29, Legion Forge)* **Hand-built test context hides integration bugs.** 29 rules errors survived a green suite because keyword tests passed window info that the real engine never supplied. For any hook/window system, keep at least one test per hook that drives real `step()` calls; an independent read-only reviewer with the rulebook found them in one pass.
- *(added 2026-10-29, Legion Forge)* **AI built in parallel with engine fixes needs a reconcile stage** (new decision kinds make it fall back). An exhaustive policy table keyed by decision kind (compile error on a new kind) plus a bench that counts fallbacks turns this into a five-minute diagnosis.
- *(added 2026-10-29, Xross Forge)* **Look for the publisher's own API before any data entry**: grep the official site's JS chunks for API hosts (`grep -ohE 'api\.[a-z.-]+/v[0-9]/[a-z/_${}]*' chunks/*.js`). Xross Stars exposed cards (with printed text and both leader sides), FAQ and restrictions as unauthenticated JSON. Give the rules agent the official FAQ in its brief: on Xross Forge the FAQ settled 4 of 7 open rulings and reversed one default.
- *(added 2026-10-29, Legion Forge)* **Wall-clock budgets make tests flaky under parallel-agent load.** Inject a clock into the AI and freeze it in tests that compare decisions; give slow simulation tests realistic timeouts until the speed budget is met. `node_modules/` (trailing slash) does not ignore a `node_modules` symlink in a worktree.
