## 3. Engine architecture (`src/engine`, about 25k lines)
**Contract** (frozen: `types.ts`, `actions.ts`, `events.ts`, `hooks.ts`, `rng.ts`, `decider.ts`, `index.ts`; changes need a matching edit to `docs/spec/00-architecture.md`):
- `step(state, action, rng?) -> {state, events, pending, rejection?}` pure reducer. One action yields zero or more events and exactly one new `PendingDecision` (null only when the phase is `ended`).
- `createGame(setup, seed, bundle?)`, `legalActions(state, pending)` (null for continuous decisions such as moves), `validate`, `replay(setup, seed, actions)`, `view(state, player)` (hidden-info redaction), `save`, `load`, `undo`.
- The engine never imports data; a `DataBundle` is passed in or registered once.
- Illegal input never throws: same state reference plus `ActionRejected` with a code (`E_WRONG_DECISION`, `E_NOT_AN_OPTION`, `E_OUT_OF_RANGE`, `E_COHERENCY`...). Only programmer errors throw `EngineInvariantError`.

**Decision model.** `PendingDecision {id, player, kind, window, context, options?, constraints?, canPass}`; the next Action carries that `decisionId`. Kinds: `deployUnit`, `chooseUnitToActivate`, `declareMove`, `moveUnit`, `declareTargets`, `allocateAttack`, `declareCharge`, `chargeMove`, `pileIn`, `consolidate`, `chooseFightUnit`, `stratagemWindow`, `reactionWindow`, `chooseOption` (generic with typed topics: `rerollOffer`, `miracleDie`, `fixRollOffer`), `commandReroll`, `confirm`. About 28 `TimingWindowId`s shared by engine, data, AI and UI.

**Decider** (`decider.ts`): `decide(view, pending, legal): Promise<Action>` plus optional `cancel()`. Human UI and AI implement the same interface. The game loop lives in the client store or `tools/sim-core.ts`; nothing else calls `step`.

**Events** (about 62 types): every rule effect emits an event; the client rebuilds everything from events plus state. Attack dice fast-rolled in batches with `rollId`/`dieIndex`.

**Determinism:** xoshiro128** RNG stored in `state.rng`; `ScriptedRng` in tests; append-only `state.log` with fnv1a `state.hash` per step; `replay` must reproduce the hash; saves `{version, engineVersion, setup, seed, actions, finalHash}`; positions rounded to 1/1000 inch; 1 unit = 1 inch, Y up, board centred at origin. Undo against the AI only for actions that rolled no dice.

**Modules:** core `reducer, state, dice, geometry, modules (ModuleTable), setup`; spatial `terrain.ts`, `los.ts` (elliptical-cylinder model blockers, per-piece cover attribution, plunging fire); rules services `attack, weapons, stratagems, effects (duration-scoped grants), leaders, transports, objectives, missions, hooks/hooks-impl/code-hooks`; `phases/{command,movement,shooting,charge,fight,legal,fightEligibility}.ts`; `engine/factions/<id>.ts` (24 files, per-faction code hooks); faction one-offs `miracle, cult-ambush, deathblow, fix-roll, teleport, pain, judgement`.

**Data-driven abilities:** abilities, stratagems, enhancements are declarative JSON (`trigger`/`when`/`effect`, scopes, durations) mapped to about 28 hook points, with `{"code": "<name>"}` escape hatches registered in `code-hooks.ts`.

## 4. Client architecture (`src/client`, about 34k lines)
- `App.tsx`, `Scene.tsx`: start, game and end screens. R3F `frameloop="demand"`, so every async change must `invalidate()`.
- `store/game.ts` (zustand): the only caller of `engine.step`; holds pending, legal, events, logs; runs the bot seat on a `setTimeout`; no-progress watchdog force-answers bot decisions.

## 11. Lessons learned / gotchas
- Freeze interfaces before fan-out (biggest rework sink); later contract changes additive and logged.
- `legalActions` must never be empty for an open decision ("any candidate passes full validation"); the game froze twice on this.
- The engine owns every number the UI shows (client `Sv - AP` ignored cover; client objective control was wrong).
- Read roll targets from state, not events (re-roll window opens before the roll event).
- Generalise each mechanism once (Mallet ended with three duplicate deferred-death mechanisms).
- Presentation is a separate layer: presented-state cursor, bot idle wait plus watchdog, `instant` speed mode.
- Prompts must name what they decide (retrofitted over about 8 commits).
- Audio: build the weapon-flavour map first; measure crest factor; describe the mechanism, not the name; "not verified by ear" when nobody can listen.
- GLBs are baked fused meshes: recolouring needs the hue-band shader, per-weapon loadouts cannot be shown (Fell-in later solved loadouts with pose variants and weapon sockets).
- Hunyuan style references turn everything blue unless `--style 0.2 --avoid`; floor-length capes need `--nocut`.
- Ops: concurrent `npm install` corrupted `node_modules`; Sonnet agents backgrounding `npm test` stall (say "foreground only"); TS 7 `paths` without `baseUrl`; Pages sub-path needs `base`/`BASE_URL`; a client agent once ran `taskkill /F /IM node.exe` and killed every node process (forbid killing by image name); harness hooks refuse edits into sibling worktrees unless the agent calls EnterWorktree first; verifier "unresolved" items are usually already fixed by the ship step (grep origin/main before dispatching fix agents); Playwright port 4173 can serve a stale sibling build.
- Owner-process: playable first; lean stages; one stop for the figure look; owner judges by playing; answer questions before building; owner is the throughput bottleneck so concept approval was delegated.
- *(added 2026-11-03, mallet-42k 2026-10-31)* **A style label in an image prompt can pull the whole look off target; describe measurements and materials instead.** Six weeks of figures were made with named model-kit labels and the owner rejected the big-eyed result; the fix was a reference photo attached to the first message plus head-heights, shoulder ratio and finish in words, and a measuring step on every result (`docs/FIGURE-STYLE.md`).
- *(added 2026-11-03, mallet-42k M10 terrain)* **Generate layouts from a source file with a script and test reachability, never hand-place.** WTC pack scaled by `wtc-to-cp.mjs`, lanes checked against the largest base.
- *(added 2026-11-03, mallet-42k M10 e2e)* **Test helpers must read the live camera, not hard-code one**, and a missing favicon fails every console-error check.
- *(added 2026-11-03, mallet-42k 88fda95)* **iOS audio unlock must keep retrying on every gesture for the session**, not unlock once on `touchstart`.
- *(added 2026-11-03, mallet-42k db1bc54)* **Do a rules-edition gap check as planning docs before touching an engine**: it found that the core rules omit the starter-set data and that frozen contracts would change.
- Folder hygiene (checked 2026-10-26, added 2026-11-03): `git status` in the local checkout shows `elevenlabs.token.rtf` untracked and not ignored (the `*.token*` gitignore gap) and a mangled folder named after a Windows temp path with the backslashes stripped. Do not copy either into a new project.
- Secrets/IP: ElevenLabs key untracked and env-only; `.gitignore` had `*.token` but not `*.token*` at first; real GW names and iconography kept as placeholders in a public repo (IP debt); personal name/path scrubbed from the tree but still in git history.
