## Using the studios from a cloud session or another machine (SSH)
*(added 2026-11-26, local-ai-studio `remote/README.md`; set up after the owner asked on 2026-11-25 for "an ssh connection to this computer that remote sessions can use to generate images, models, sounds, voices, and music")*

EVILAEGIS runs Windows OpenSSH Server and is on the owner's Tailscale network. The studios still listen on 127.0.0.1 only; remote callers reach them through SSH port forwarding, so **every API in this file works unchanged at `http://127.0.0.1:<port>`** once connected.

**From a cloud session (claude.ai/code):**
1. Run `bash tools/connect-gpu-pc.sh up` from this KB. In a game repo with the KB submodule, run `bash docs/knowledge-base/tools/connect-gpu-pc.sh up`. It installs Tailscale in userspace mode (no root, no TUN) and joins the tailnet as an ephemeral `tag:cloud` node. It then SSHes to EVILAEGIS with the restricted cloud key, starts any studio that is down, forwards 7860, 7870, 7880 and 7890 to localhost, and prints `localhost:<port> -> HTTP 200` per studio.
2. Call the APIs with the proxy bypassed. Cloud VMs set `HTTPS_PROXY`, so use `curl --noproxy '*' http://127.0.0.1:7880/...` or set `NO_PROXY=127.0.0.1,localhost`.
3. `connect-gpu-pc.sh status` shows the studios as the PC sees them; `down` closes the forwards and leaves the tailnet.
- **Needs three variables in the cloud environment**: `TS_AUTHKEY`, `EVILAEGIS_SSH_KEY` and `EVILAEGIS_SSH_USER`, which the owner keeps in the **Default** environment. If the script reports one missing, the session is on another environment, so ask the owner. Never put them in a repo or a log.
- **The cloud key's limits**: it can start the studios, report their status and forward the four studio ports. It has no shell, no file copy and no ComfyUI port 8188. Any other command just prints status. The tailnet policy also limits `tag:cloud` to port 22 on EVILAEGIS.
- **Moving files**: inputs go in the POST body (reference images, the foley video and voice-clone clips as data URLs; Hunyuan Studio's image as raw base64). Outputs come back over HTTP: Flux, Audio and Video use `GET /files/<id>/<file>`; Hunyuan uses `GET /api/jobs/<id>/files/<file>`. Save outputs into the repo and push, because the container is reclaimed.
- **Hunyuan Studio over HTTP** (`server.js`, read 2026-11-26): a text job is `POST /api/jobs {mode:'text', prompt, params:{conceptModel:'sdxl'|'klein'|'dev'|'schnell', candidates 1-8, octree 384, steps 50, faceCount 40000, texture:true, texRes 512|1024|2048, cutBase, seed}}`; an image job is `{mode:'image', name, image:<base64 PNG>, params}`. A text job stops at `status:'awaiting_pick'`; choose with `POST /api/jobs/<id>/pick {index}`. It ends `completed` (files include `shape.glb` and `textured.glb`) or `failed`. Flux and Audio jobs end `done`, `failed` or `cancelled`.
- Poll `GET /api/jobs/<id>` in short calls; one long wait hits the tool timeout.
- **If the variables are missing or the PC is off**, fall back to the older route: a Claude session on EVILAEGIS, messaged from the cloud session ([annals-of-scrivenearth.md](annals-of-scrivenearth.md), [xross-forge.md](xross-forge.md)). Cloud sessions still cannot attach EVILAEGIS folders through Remote Control ([legion-forge.md](legion-forge.md)).

**From the Mac or Alteisen:** each gets its own full-shell key (local-ai-studio `remote/README.md`, "Adding a machine"). Connect with `ssh evilaegis`, at home on 192.168.4.209 or over the tailnet on 100.66.173.113. A Claude Desktop **SSH environment** pointed at `evilaegis` runs a whole session on this PC, with every studio, ComfyUI and the Hunyuan scripts. Windows hosts need Claude Desktop v2.31226.0 or later, and the login shell is cmd.exe.

GPU etiquette applies unchanged to remote callers ("Owner rules for GPU work" below). Before submitting, check `GET /api/status` on each studio for `running` and `queued`: another session or the owner may hold the GPU.

## Audio Studio job parameters (from `server.js` `sanitize()`)
- **music:** `{mode:'music', prompt (style line), lyrics ('[Instrumental]' when empty), duration 10-240 s (default 60), steps 1-30 (default 8), guidance (1), shift (3), bpm 10-300 (120), key (ACE keys, 'C major'), timesig '2'|'3'|'4'|'6', language, batch 1-2, seed}` -> `audio_0.flac`. Measured: 30 s instrumental 11 s cold, 40 s song 8 s warm.
- **sfx:** `{mode:'sfx', prompt, negative, seconds 1-47 (default 10), steps 1-100 (default 50), guidance 0-15 (default 5), batch 1-4, seed}` -> `audio_0..n.flac`. Measured: two 6 s effects in 5 s.
- **foley:** `{mode:'foley', prompt, negative ('noisy, harsh'), duration 1-60, steps, guidance, seed, video (data URL)}` -> audio plus `video_with_audio.mp4`.
- **voice:** `{mode:'voice', model:'chatterbox'|'chatterbox-mtl'|'chatterbox-turbo'|'qwen-clone'|'qwen-design'|'qwen-custom', text (<= 6000 chars), language, refText, instruct (voice description for qwen-design, delivery note for qwen-custom), speaker (qwen-custom presets, e.g. 'Vivian'), exaggeration 0-2 (0.5), cfg 0-1 (0.5), temperature (0.8), seed, ref (data URL of a 5-10 s clip for clone models)}` -> `voice.wav`. Measured: 8-10 s per sentence plus 7-8 s model load.
- Job folder `audio-studio/outputs/<job-id>/` holds `job.json` (params, log, `audios`) and the files. Weights are already downloaded (`ace_step_1.5_turbo_aio.safetensors`, `stable_audio_open_1.0.safetensors`, `foley/hunyuanvideo_foley_fp8_e4m3fn.safetensors`; Qwen and Chatterbox English weights cached).
- *(added 2026-11-13, stellar-derelict M6)* Measured on the RTX 5080: Stable Audio Open about 5 s a job, ACE-Step about 10 s a 120 s track, Qwen voice design about 8 s a line; 79 jobs (54 effect files, 7 tracks, 34 lines) in about 20 min. Takes need levelling before anyone listens (see [gotchas.md](gotchas.md) "Audio"); a `--reroll n` seed offset gives another take for the same id.
- Prompt lessons (ElevenLabs era, likely to transfer): describe the mechanism, not the brand; state exclusions ("no music, no voices"); measure crest factor (gunshots need >= 8); layer with `compose-audio.ts` when a single prompt can't get there.

## Hunyuan3D figure pipeline (outside the repo)
- `%USERPROFILE%\Hunyuan3D-2` (Python 3.11 venv: SDXL concepts, cutout, 2.0 paint, viewer on 8765) and `%USERPROFILE%\Hunyuan3D-2.1` (Python 3.10 venv with bpy: 2.1 shape, finalize). Weights as plain files under `%USERPROFILE%\.cache\hy3dgen`. Do not upgrade `transformers` 4.48.3 / `diffusers` 0.32.2 in the 2.0 venv. `UV_SYSTEM_CERTS=1`.
- Inputs: `units.json` `{slug: {prompt, height (inches), base (mm)}}` (251 entries on 2026-10-17) and `picks.json` `{slug: seed | absolute image path}`; write both without a UTF-8 BOM (PowerShell 5.1 `Out-File` adds one).
- *(added 2026-11-13, stellar-derelict M5)* `stage_finalize.py` reads `units.json` from the `Hunyuan3D-2` folder it runs in, not from the `PICKS` path, so a game's units must be merged into that file (737 entries on 2026-11-12, no slug collisions). Props: `stage_shape.py --faces N --nocut` at the shape stage is the only way to meet a triangle budget (a painted mesh will not simplify). 11 models (8 figures, 3 props) in about 25 min of GPU, about 430 KB a figure after `models:optimize`.
- Stages: (1) `concepts_sdxl.py` (6 SDXL candidates; `--style 0.2 --avoid "blue armour"` for non-Marine factions) or an external concept image (Gemini/Flux) -> (2) `stage_cutout.py` -> (3) `stage_shape.py --only <slugs> [--nocut <slug>]` (2.1 venv, about 90 s, auto-cuts the display base) -> (4) `stage_paint.py --only <slugs>` (about 20 s) -> (5) `stage_finalize.py <repo>\public\assets\models <slugs>` (scales to inches, black base, matte, preview PNGs and `final_contact_*.png` sheets). Whole 5-unit run about 12 min. One GPU job at a time.
- Hunyuan Studio UI wraps the same stages with quality presets (Fast 256/20, Standard 384/50, High 512/50), face count, texture 512/1024/2048, remove display base.
- Terrain: `terrain_*.py` scripts; painted Gemini concepts beat grey-resin SDXL (owner rejected the grey batches); `terrain_post.py --faces 9000`; decimate to about 6k tris for frame time; image-to-3D cannot do flat terrain (keep flats procedural).
- Weapon loadouts (Fell-in M5): figure concept edited into a stance with Flux klein image edit, Hunyuan 3D via the studios, weapon GLBs on measured hand sockets (`tools/local-gen/gen-poses.mjs`); true rigging rejected on fused Hunyuan meshes.
- Post-process in repos: `tools/models/optimize.mjs` (dedup, prune, weld, WebP <= 1024, meshopt); `GLTFLoader` then needs `setMeshoptDecoder` or every GLB silently falls back.
- Licence: Hunyuan3D under Tencent's non-commercial community licence.

## Concept image sources
- **Gemini via Claude in Chrome on this PC** (never the Mac, never the built-in browser): one chat per faction; base figure then edit variants ("start from image N, keep everything, change only X"); export via in-page JS (`?alr=yes` fetch for lh3 URLs, canvas for blob:) as one JSON bundle per tab; about 30 images per evening cap; reference images only through the hidden file input (never the clipboard, after a 2026-10-05 leak). The current recipe is Mallet 42k `docs/FIGURE-STYLE.md` (rules.md rule 7), which replaced Mallet's earlier figure handoff doc.
- **Flux Studio (local, free):** text-to-image and image edit; no negative prompt (say "wordless and untitled, full-bleed"); a proper noun in a clause invites lettering; name the thing instead of "figure"/"creature"; review on labelled 4x4 contact sheets.
  - *(added 2026-11-15, stellar-derelict M9; RTX 5080, klein, batch of 4)* 16 s at 1 MP text-to-image (36 s with the model load), 26 s at 2 MP 16:9, 26 s for an image edit with one reference. `megapixels` takes 1 or 2 only. **An image edit ignores `aspect`**: a 832x1216 reference came back 1184x880, so crop at publish. Start the studio detached with its PID in `%TEMP%\flux-studio.pid`; it starts ComfyUI itself on the first job.
  - *(same)* Prompt forms that worked first time: **tiles** "a top-down orthographic photograph of one square <thing> filling the whole frame edge to edge ... flat even lighting with no cast shadows and no perspective, a square game texture" (pick the full-bleed candidate; about one in four has a white margin); **decals** "... seen from directly above, centred with a wide empty margin on every side, isolated on a plain pure white background", then alpha from luminance; **key art** name what is dark and the one or two lights, state the palette once, end "cinematic still, realistic, deep blacks, ... wordless and untitled, full-bleed".
  - *(added 2026-11-15, stellar-derelict M10)* **Damage must be the subject, not an adjective**: "worn, scratches, grime" gives clean panels; "raked by huge claws: five long deep parallel gouges slashed diagonally across the whole panel, the steel torn open to bright bare metal with curled ragged edges" gives a wreck in 4 of 4. Flux paints bare steel blue-grey: keep the colour and pull it toward neutral at publish (sharp `recomb`). A texture with fire in it keeps its own exposure (do not level it with the rest).
- **SDXL (local, free):** fallback; cannot hold an exact head ratio; 77-CLIP-token prompt limit (style first, generic tail last).

## Figure standard (Mallet 42k `docs/FIGURE-STYLE.md`, approved 2026-10-31)
*(rewritten 2026-11-03 from Mallet 42k `docs/FIGURE-STYLE.md`)* Serious and highly detailed, like a premium painted miniature. About 2.8 head-heights (2.8-3.5 across the two approved references); head or helmet about 35% of height and about 0.55 of the shoulder span; very broad armoured shoulders about 1.8 times the head's width; chin to belt about 0.75 of a head; hips to soles about one head, legs short and thick; big boots in a wide planted stance; gloved fists about a third of the head's height; oversized weapons; covered or stern face, never big round eyes; matte realistic paint with edge highlights, rivets and panel lines; plain round black base, white background, no text. Attach `figure-style-reference.jpg` to the first message of each army chat. Prompts give measurements and materials only, never the labels in rules.md rule 23. Check the image, not the prompt. Reject duplicate/extra weapons, missing limbs, fused parts, garbled faces, text, cropped base, wrong wargear. The earlier standard (Mallet, 2026-10-05: about 2-2.5 heads, head about 40% of height, rounded shapes, glossy finish) was retired on 2026-10-31 because its labels pushed the image model to big-eyed, baby-faced figures. (Whirr/WarMech/Dead of Winner/Fell-in used 3-5 head proportions stated in plain words.)
