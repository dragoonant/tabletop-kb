# Xross Forge (Xross Stars) — living entry

Repo `dragoonant/xross-forge` (public), started 2026-10-29 from a **claude.ai cloud session**. Decisions: `PLAN.md` (D1-D15); rules: `docs/rules.md`, `docs/rulings.md`; sources: `docs/sources.md`; rights: `docs/rights.md`; donor map: `docs/PORTING.md`. **This entry is updated at the end of every milestone.**

## 1. Overview
- Xross Stars (クロスタ): a Japanese TCG from Brave group, developed by Game & Co. and SAMURAI KOBO, released 2025-08-22. Cards are real VTubers and streamers (VSPO!, Crazy Raccoon, Neo-Porte, REJECT). Each player has 4 two-sided leaders that awaken when they down an enemy leader, a 50-card deck of attack and memoria cards, and a 5-card tactics deck. PP grow 3/4/5 by round; best of 3 rounds, or a one-round quick match (PLAN D1, `docs/rules.md`).
- The owner called it "Xross Gates" at kickoff; no game of that name exists, and the owner confirmed Xross Stars (2026-10-29).
- Owner decisions 2026-10-29 (do not re-ask): real names with our own generated art of each avatar, no cloned voices (D2); **scaffold from lorecannae** over GRAND LINE (D3, owner's suggestion after a side-by-side); ~~Gemini image API and ElevenLabs run from the cloud session~~ (D4, D5) **superseded by D17: M5 and M6 ran on the owner's PC's local Flux Studio and Audio Studio** ("Run M5 and M6 on this computer", a desktop session after the cloud session; no cloud key ever existed on the PC, and the $25 budget D6 went unspent); esports-broadcast look (D7); first slice = the original starters ST01 vs ST02 (D8).

## 4. Lessons so far
- *(M0)* **Grep the publisher site's JS bundle for API hosts before planning data entry.** The Next.js chunks of xross-stars.com named `api.xross-stars.com/v1/cards`, `/faq` and `/cards/restrictions`: an unauthenticated JSON API with every card's stats, printed text and awakened stats, plus 136 official FAQ entries. Filters are singular (`product=ST01`, `color=red`); `limit=100&page=N` pages. This replaced the image-reading and fan-bundle routes Legion needed (README gotcha, 2026-10-29).
- *(M0)* **Image-only PDFs with CID fonts**: `pdftotext` returns nothing and `pdftoppm` prints font errors but still renders legible pages. At 160 dpi an agent read all 19 pages of the Playing Manual by eye. Check one page image before handing them off.
- *(M0)* **Starter quantities came from the product page's card-list images**, cross-checked: each list sums to 50 and every API `is_ace` card is x2. (The coordinator first claimed the x2 cards were exactly the ACE cards; the M1 agent found two non-ACE x2 cards, and full-size crops confirmed the counts. Verify a cross-check claim before writing it down.) The ST01/ST02 page lived at `/product/st01-02`, not `/product/ST01` (404). Find the page through a web search when the obvious slug fails.
- *(M0)* **Give the rules agent the official FAQ from the start.** It wasn't in the brief; the coordinator's check afterwards confirmed 4 of the 7 open rulings and **reversed one default**: R-025 had awakening once per multi-attack card, but FAQ #81 says after each downing attack.
- *(M0)* **Starters can be illegal as sold.** エナジーチャージャー was banned on 2026-07-13 but ships in both original starters (PLAN D15: play them as printed).
- *(M0)* The Wayback Machine resets connections from the cloud session; affiliation tags exist in the card API's tag list but not on each card, and no tag filter works (PLAN D13: a hand table).
- *(M0)* The session's stop hook asks to commit untracked files while background agents are still writing them. Don't commit half-written agent output to quiet it: commit each agent's files by explicit path once it hands back and its gate passes.
- *(M2/M3)* **Signal the frozen contract with a file and start the UI on it.** The engine agent wrote `tools/out/m2-contract-ready` when `docs/ENGINE-API.md` was complete; a background `until [ -f … ]` wait woke the coordinator, which then launched the UI agent. The UI was built against the contract while the engine was still being written, and integration needed no engine changes. Only additions were allowed after the freeze, each logged at the bottom of the contract.
- *(M2)* **Back up unreviewed agent work without touching the shared index**: build a commit through a temporary index (`GIT_INDEX_FILE=<tmp> git read-tree HEAD && git add -A && git commit-tree $(git write-tree) -p HEAD`) and force-push it to a backup branch. The agents' working tree and the real index are untouched. Deleting that branch afterwards was refused by the session's git proxy ("remote end hung up"), so expect to leave it for the owner.
- *(M2)* **The rules review found 0 WRONG on a small ruleset whose open rulings were checked against the official FAQ first** (compare Legion's 29). Choose the reviewer by budget: on Xross Forge it cost 0.30M and confirmed the slice rather than fixing it.
- *(M4)* **A "missed lethal" counter found a weight bug that win rate hid**: the round-win weight (900) was low enough that the AI sometimes passed instead of downing the opponent's last leader, and it still beat random 100%. Count, per tier, the turns with zero plays where an affordable attack would have downed a leader; the random control showed 96 missed lethals, the fixed AI 0. The search was saturated (a 4,000-node search did no better), so the evaluator was the limit, not the depth.
- *(M5)* **"Run it on this computer" after a cloud plan means the local studios, and the cloud keys were never going to appear.** The cloud session wrote D4/D5 around `GEMINI_API_KEY` / `ELEVENLABS_API_KEY`; the PC has neither (shell, user and machine scope checked; lorecannae's PLAN had already recorded "cloud keys are dead"). Check the key before planning a paid pipeline; the free local studios (`local-ai-studios.md`) did the whole slice in under an hour of GPU time.
- *(M5)* **Look at the official faces before writing an identity table.** The ST02 leaders (Crazy Raccoon) are cartoon mascots on the cards (a horned-headset girl, a pirate with a hook, a red-haired boy, a white cat), so the "real person's face" concern in `docs/rights.md` did not arise for the first slice; the VSPO! leaders are anime avatars. 58 reference images were fetched from the API's `image_url` / `awaken_image_url` into gitignored `docs/sources/images/`, sheeted with `tools/contact-sheet.ps1`, and read once; no image input was ever used.
- *(M5)* **Audition on klein wins for a broadcast anime look**: in the first pass A (FLUX.2 klein, anime key-visual STYLE) beat B (FLUX.1 dev, same STYLE: softer, drifted from the costume clauses, 3x slower, non-commercial licence) and C (klein painterly: faces drifted toward photo-real); in the cloud pipeline's 10-candidate audition the same klein picked "A neon cel-shading" over the gritty key art (photo-real drift) and the idol/watercolour looks. klein renders a 1 MP plate in 5-9 s. Its one tic: it fills an "esports stage" with background monitors that carry faux lettering; the QC pass has to look at the edges, not just the figure.
- *(M5/M6)* **Check `origin/main` before building, and again before pushing: a cloud session can be pushing the same milestones.** The desktop session built M5/M6 from the M4 tree while the cloud session pushed its own M5/M6 pipelines and M7 polish (54 files, 5,000 lines). The push was refused as non-fast-forward; the reconciliation that cost least was to park the first pass on a branch, take the newer tree whole (its client already wired art and audio), and add local backends that write the masters its pipelines expect (`gen-art-local.mjs`, `gen-audio-local.mjs`), re-rendering in its portrait sizes. Half a day of a desktop session was redone in an hour of GPU time.
- *(M5)* **Tooling traps on the desktop session:** the Bash tool rejects a long heredoc with a stray quote ("unexpected EOF while looking for matching `'`"), so JS files went through the Write tool; a PowerShell `-Dir docs\sources\images` argument from bash loses its backslashes (`docssourcesimages`, "0 images"), so pass forward slashes; `loadPage()` in `tools/test.mjs` returns the window shim, not `XS` (read `.XS`).
- *(M6)* **The M1 sound-manifest contract ("a cue per card face") was the wrong unit**: the director fires on log tags, so `validate-data` now requires a delivered clip per cue tag of `data/audio-cues.js`, and the self-test punches one hole in each manifest to prove the rule bites (a complete manifest would otherwise pass the "did it bite" check for the wrong reason). The cloud session's M6 left `REQUIRE_SOUND` false with the old rule in place; flipping it is part of generating the assets.
- *(M6)* **An "original announcer voice" without a cloud voice-design API**: Qwen3-TTS Voice Design on the local Audio Studio makes a voice from a written description once (`audio/masters/voice-design-preview.wav`), and every line is then spoken by cloning that preview, so the seven lines share one voice and no real person is involved.
- *(M4)* **Gate the opponent's rollouts behind the base plan**: hard's opponent-reply rollouts, given an unrestricted veto, refused 23 available downs in 800 games and lost to normal. Letting rollouts arbitrate only between plans within 80 points of the best restored 53-55%.
- *(M5/M6)* **Cloud environment variables reach a session only when its VM restarts.** The owner added keys mid-session (the phone app has no environment editor; claude.ai/code in a phone browser does: the caret after the session title → Edit cloud environment). Build every paid pipeline with `--dry-run`, `--mock` (generated stand-in files) and a local fake HTTP server so the whole chain is proven before the first paid call; then `--probe` first.
- *(M5-M7)* **Three parallel agents with disjoint files and one written interface** (M6's `XS.Audio` contract was in both briefs; M7 owned every UI file, index.html and tests.html; M5/M6 owned tools and data only). When M6 finished first, the coordinator relayed its real exports and script lines to the still-running M7 by message instead of editing M7's files. M6's own files were committed alone (minus its test, which needed an M7-owned line) and gated in a clean worktree.
- *(comp decks)* **Official deck-builder share links are the best decklist source** (`api.<site>/v1/decks/<id>` returns the exact list); retailer recipe pages are second; shop "sample recipes" are not competitive evidence. Select by source quality and say what was swapped (three BP05 samples were replaced by tournament-sourced alternates; 126 -> 92 new cards).
- *(comp decks)* **Split card scripts by product before fanning out authors**: one helpers file exporting a kit, one file per product, and a final file that deep-freezes. Four agents wrote 92 cards in parallel with no conflicts; each owned its data file and a pre-registered test file. Ops a card lacked were marked `{unimplemented}` and closed in one engine pass afterwards.
- *(comp decks)* **A choice over a hidden pool must always be asked**, even with zero candidates (min 0, empty options), or the opponent learns whether a hidden card qualifies. The independent reviewer found this in free play and look-and-pick after four green authoring agents.
- *(comp decks)* **Driving the owner's PC from a cloud session**: `send_message` to the PC's Remote Control session needs a one-time owner approval (`confirm_repository_trust`); after that the PC session took self-contained jobs (branch, keys to render, QC notes, exact files to commit) and replied by session name. Give it a dedicated branch so main stays green while it pushes, and tell it to `pull --rebase` before pushing.
- *(comp decks)* **CI on safety snapshots sends failure emails**: pushing ungated work-in-progress snapshots to a backup branch ran CI on half-edited trees (20 failure emails). Exclude the backup branch in the CI trigger from the start, and keep known-red intermediate commits off pushed branches.
