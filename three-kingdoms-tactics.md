## 1. Overview
- **The series' first original game (not a port).** It is a spiritual successor to Koei's Dynasty Tactics (2002) and Dynasty Tactics 2 (2003, both PS2; Japanese title Sangokushi Senki). The ruleset is our own, so "fidelity is the product" (README rule 2) becomes "the spec is the product": rules are written with ids first, every ambiguity is a `RULING:` line, and balance changes need a sim or bench result.
- Owner decisions 2026-10-31 (do not re-ask): browser/TypeScript on the sibling stack (D1); first milestone one playable battle (D2); art direction "from the knowledge base", meaning MGSD figures (D3); presentation concept **war-council sand table** (D4); first battle **Daxing Hill**, Romance ch.1 (D5); push to `main` + Pages after each stage (D6).
- Defaults taken: square grid with 4 facings; side phases; signature **linked stratagems** (tag/`follows` chains of up to 4 links with a sworn-brother bond bonus); historical names from the public-domain novel, with no Koei names, art or UI.

## 4. Lessons for the series
- *(added 2026-11-01, three-kingdoms-tactics)* **Paper-sim a run economy with blunt policies before building it.** Four utility policies (benevolent, ruthless, balanced, careless) over 500 seeds each, per-stop choice shares and a "picked 95%+ by every sensible policy" dominance check showed in minutes that the first-pass numbers were unwinnable (finale tuned for 8,000 men, armies of 2,500) and that 8 choices were dominant. Deterministic policies flip a choice from 0% to 100% on a small number change, so give each choice an axis one policy wants (rice, men, Renown, days) instead of tuning margins. Say plainly that the battle model is a placeholder for the real AI bench.
- *(added 2026-11-01, three-kingdoms-tactics)* **Generate the spec's tables from the data file.** The era-1 stop tables and echo table in the spec are printed from `era1-stops.json` by a small script, so twenty rounds of tuning never left the prose and the numbers out of step; the spec says the JSON wins on any disagreement.
- *(added 2026-11-01, three-kingdoms-tactics)* **Set-dressing around an orbit camera blacks out low views.** The "wall" the owner saw at low camera angles was the tent cloth ring (14 panels about 17 tiles out): the camera orbits outside it, so near panels filled the screen. Fade the camera-side dressing by angle, and keep an e2e test that reads pixels over tiles from four sides at the lowest pitch.
- *(added 2026-11-01, three-kingdoms-tactics)* **Portraits from your own figures first, generated paintings later at the same paths.** Rendering busts of the procedural rigs gave every officer a face in one run with no token; a generator (`tools/portraits/gen-hf.mjs`, token only from the env, prompt lint, `--dry-run`) can overwrite the same files once a token exists. Prompt lint that bans negation words forces positive phrasing ("wordless and unlettered, full-bleed").
- *(added 2026-11-01)* **Direct cinematics as beat lists with ids, render them deterministically, review by contact sheet.** Each cut-in is a pure function of time, so a headless renderer steps t at 30 fps into an MP4 plus one labelled frame per beat. The owner gives notes by beat id ("B4: hold longer"). This works even under SwiftShader at 2-3 fps.
- *(added 2026-11-01)* **Freeze a joint contract before figures and animation are built in parallel.** `rig.ts` (joint names plus a placeholder builder) let the figure agent and the cut-in agent work at the same time, and it is the seam where generated GLBs will plug in later. Cost: the placeholder was half the real height, so the scene agent had to rescale from `rig.height` after the merge. Put scale in the contract.
- *(added 2026-11-01)* **Owner reversals land mid-stream; record them as decisions with the owner's words.** Bases went from part of the concept to "I don't want them on bases ... Correct everywhere" within an hour. PLAN D19-D24 hold the quotes, so no later session re-litigates them.
- *(added 2026-11-01)* **Animated walking conflicts with fused generated meshes** (README rule 15: skeletal animation was dropped for Hunyuan GLBs). Raise it as an open M5 decision before the first Hunyuan run: generate parts per joint, auto-rig, or keep GLBs static.
- *(added 2026-11-01)* **Locomotion phase must come from distance travelled, not time** (phase = distance / stride); otherwise speed changes make feet skate. A unit test that tracks each boot's lowest vertex along a path catches it.
- *(added 2026-10-31)* **Pre-register content slots before fanning out builders.** The engine stage created valid stub battles and scene files already imported by the registry, so four parallel builders only replaced their own files and never touched an index. Merge conflicts were limited to one shared test.
- *(added 2026-10-31)* **Parallel builders all trip on the same shared tool; fix it before the fan-out.** All four battle builders found that `ai-bench` hard-coded the first battle's enemy side and that a data test asserted "every later battle is a stub"; each worked around it separately. A 10-minute pre-flight (run every tool on a non-default stub) would have saved four rediscoveries.
- *(added 2026-10-31)* **Flow tests must not depend on balance.** When the AI got stronger, the campaign flow tests (which win battles with the bot) went red. A `?bot=random` / `setBotTier()` switch lets flow tests pin the enemy to the random tier; balance lives in the bench, not in e2e.
- *(added 2026-10-31)* **Benches are rules fuzzers.** The AI bench on real battle data found two engine edge cases (a unit swayed on its old side's gate; a provoke outliving its provoker) that 200-game random sims never hit.
- *(added 2026-10-31)* **Keep the shared index out of in-flight agents' way.** While an agent is still writing, back up its work with a temporary index (`GIT_INDEX_FILE=... git add -A && git commit-tree`) pushed to a `wip/` branch; this answers the stop hook's "uncommitted changes" without committing ungated work to main or touching the agent's index.
- **A new repo's first Pages deploy fails at `actions/configure-pages`** until Pages is enabled with Source "GitHub Actions"; the default GITHUB_TOKEN cannot enable it. Ask the owner at kickoff.
- **Original games need a spec with rule ids before code.** Writing `10-rules.md` with ids and numbers let one Sonnet agent build the whole engine in one pass, logging 17 rulings instead of blocking.
